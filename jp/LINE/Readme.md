# LINEを活用した受託開発業務自動化システム

日本のお客様からのシステム・アプリ開発に関するお問い合わせを受け付け、

要件整理、打ち合わせ予約、情報共有までを一貫して支援する、

実運用を前提とした業務自動化システムです。

これは単なるチャットボットではありません。

AI に自動応答させることだけを目的としたシステムでもありません。

実際の業務で継続して利用できることを前提に設計・開発を続けている、
バックエンドシステムです。

---

# このプロジェクトについて

受託開発のお問い合わせは、

一回の会話だけで完結するものではありません。

開発したい内容を確認し、

不足している情報を整理し、

打ち合わせを予約し、

社内で共有し、

案件として進めていく必要があります。

つまり必要なのは、

チャットを返す仕組みではなく、

**業務全体を支える仕組み**です。

このプロジェクトでは、

LINE を入口として、

お問い合わせから社内運用までを

一つの業務フローとして設計しています。

---

# なぜこのシステムを作ったのか

LINE Messaging API と AI を接続するだけであれば、

それほど難しいことではありません。

しかし、

実際の運用では、

それだけでは十分ではありません。

例えば、

- 同じ Webhook が複数回送信される
- AI の応答が遅くなる
- Reply Token が失効する
- 数日後に会話が再開される
- 打ち合わせ日程が変更される
- 担当者への情報共有が必要になる

このような問題は、

AI の性能だけでは解決できません。

必要なのは、

運用を前提としたシステム設計です。

このプロジェクトでは、

AI を一つの構成要素として利用しながら、

実際の業務を止めないことを最優先に設計しています。

---

# システムの役割

このシステムは、

お問い合わせ対応を自動化するだけではありません。

以下の業務を一つの流れとして管理します。

- お問い合わせ受付
- 要件ヒアリング
- 会話状態の管理
- 打ち合わせ予約
- Google Workspace との連携
- 社内通知
- 業務フロー管理

お客様との会話を、

実際の業務へつなげることが、

このシステムの役割です。

---

# システム構成

```text
お客様
   │
   ▼
LINE公式アカウント
   │
   ▼
Webhook
   │
   ▼
署名検証
   │
   ▼
重複イベント検出
   │
   ▼
イベント処理
   │
   ▼
AI による意図解析
   │
   ▼
入力値・状態の検証
   │
   ▼
業務フロー
   │
   ├────────────┐
   ▼            ▼
予約管理     会話状態管理
   │            │
   └──────┬─────┘
          ▼
Google Workspace
(Calendar / Sheets)
          │
          ▼
通知・情報共有
```

各コンポーネントは、

役割ごとに分離されています。

そのため、

一つの機能を変更しても、

他の機能へ影響が広がりにくい構成になっています。

# 主な機能

このシステムは、
AI に会話をさせることではなく、

受託開発のお問い合わせを
業務として適切に処理することを目的にしています。

それぞれの機能は独立しているのではなく、

一つの業務フローとして連携しています。

---

## お問い合わせ受付

営業時間に関係なく、

LINE からのお問い合わせを受け付けます。

受信したメッセージは、

その場で終わるチャットではなく、

案件化までを見据えた業務データとして扱います。

---

## 要件ヒアリング

開発相談では、

最初から必要な情報がすべて揃うことはほとんどありません。

そのため、

会話の流れに合わせて、

不足している情報を少しずつ整理していきます。

- 開発内容
- 必要な機能
- ご予算
- 希望納期
- その他の要望

会話を続けながら、

要件を整理できるよう設計しています。

---

## 会話状態の管理

お問い合わせは、

一度で終わるとは限りません。

数時間後、

あるいは数日後に、

再び相談が始まることもあります。

そのため、

現在どの段階まで話が進んでいるのかを

システム側で管理しています。

これにより、

途中からでも自然に会話を再開できます。

---

## 打ち合わせ予約

要件整理が完了すると、

そのまま打ち合わせ予約へ進めます。

予約情報は

会話とは別に管理され、

業務データとして保持されます。

---

## Google Workspace 連携

予約情報やお問い合わせ内容は、

必要に応じて

Google Calendar や

Google Sheets と連携できます。

お客様との会話だけで終わらず、

その後の業務まで支援します。

---

## 社内共有

お問い合わせ内容は、

担当者が確認しやすい形で整理されます。

運用状況の共有や、

案件管理にも利用できる構成になっています。

# 実運用から得た改善

このシステムは、
最初から現在の構成だったわけではありません。

実際に開発・検証を進める中で見つかった課題を一つずつ改善し、
現在の設計へと発展してきました。

ここでは、
実運用を想定した開発の中で得られた代表的な改善例を紹介します。

---

## Webhook の重複受信

LINE Messaging API では、
同じイベントが再送される場合があります。

このイベントをそのまま処理すると、

同じ予約が複数回登録される、

同じ通知が繰り返し送信される、

といった問題が発生します。

そのため、

イベント ID を利用した重複検知を実装し、

一つのイベントは一度だけ処理されるよう改善しました。

これにより、

再送が発生しても、
業務データの整合性を維持できます。

---

## Reply Token の制約

Reply Token は、
一定時間を過ぎると利用できなくなります。

AI の応答時間や、

外部 API の処理時間によっては、

返信できないケースも発生します。

そのため、

返信方法を用途ごとに分離し、

必要に応じて Push Message を利用する構成へ変更しました。

これにより、

処理時間に左右されにくい、
安定したメッセージ送信を実現しています。

---

## AI 応答時間への対応

AI の応答時間は一定ではありません。

ネットワーク状況やモデルの負荷によって、

応答までに時間がかかることがあります。

そのため、

AI の応答速度に依存しないよう、

非同期処理を前提とした構成へ改善しました。

システム全体が停止することなく、

必要な処理を継続できるよう設計しています。

---

## 会話状態の管理

お問い合わせは、

一度で完結するとは限りません。

数日後に相談が再開されることも珍しくありません。

そのため、

現在の相談状況をアプリケーション側で保持し、

途中からでも自然に会話を再開できるようにしました。

チャット履歴だけではなく、

業務の進行状況を管理している点が特徴です。

---

## 外部サービスとの連携

お問い合わせ対応は、

LINE の中だけで完結するものではありません。

予約、

情報共有、

進捗管理など、

複数のサービスとの連携が必要になります。

本プロジェクトでは、

Google Workspace を中心に、

外部サービスとの連携を独立した責務として設計しています。

一つのサービスに問題が発生しても、

システム全体へ影響が広がりにくい構成を採用しています。
