# FORGE — Portfolio Website

> 複雑な技術を、理解できる言葉と、信頼できる証拠に変える。

AI支援開発における「プロジェクトの継続性」をテーマにした、技術プロダクト向けポートフォリオサイトです。

単に見栄えのよいページを作るのではなく、初見の方が短時間で価値を理解し、実装状況と検証結果まで確認できる構成を目指しました。

---

## このサイトで伝えていること

FORGEは、AIとの開発セッションが変わっても、プロジェクトの背景・知識・意思決定を引き継ぎ、作業を継続できる環境を目指して開発しているプロジェクトです。

このポートフォリオでは、内部実装を公開する代わりに、次の3点へ焦点を絞っています。

- どのような問題を解決するのか
- 実際の利用フローで何が起きるのか
- 公開可能な範囲で、何を実測・再確認したのか

技術の複雑さをそのまま見せるのではなく、依頼者・利用者の視点から理解できるストーリーへ再設計しています。

## 制作で重視したポイント

### 1. 技術を「依頼判断できる情報」に変換

専門用語の羅列ではなく、課題、体験、証拠、実装範囲、今後の方向性という順序で情報を設計しました。技術者以外の方でも全体像を追え、技術者には検証姿勢が伝わる構成です。

### 2. Evidence-first の見せ方

強いコピーだけで信頼を求めず、公開可能な実測結果を独立したセクションとして提示しています。また、実装済みの内容と今後の方向性を分け、完成度を誇張しない表現にしています。

### 3. プロダクトの性格に合わせたビジュアル

暗い背景、抑えたガラス表現、エンバー色のアクセント、モノスペース書体を組み合わせ、開発ツールらしい精密さと熱量を両立させました。装飾は情報の優先順位を壊さない範囲に限定しています。

### 4. スクロールを説明手段として使用

スクロール連動のキャンバス表現、段階的なハンドオーバー表示、セクション reveal、控えめなカードインタラクションを実装しています。アニメーションは飾りではなく、情報が整理され、次の状態へ進む過程を伝えるために使用しています。

### 5. 静的サイトとして完結

バックエンドやビルドサーバーに依存せず、HTML / CSS / Vanilla JavaScriptのみで構成しています。GitHub Pagesのような静的ホスティングへ、そのまま配置できる構造です。

## この制作から確認できる対応領域

- 技術プロダクト、SaaS、開発ツールのランディングページ
- 複雑なサービス内容の情報設計
- 日本語でのコピー構成とセクション設計
- デザインから静的フロントエンド実装までの一貫対応
- Canvas、スクロール、Intersection Observerを使ったインタラクション
- Desktop / Mobileを考慮したレスポンシブ設計
- 実測結果を使ったポートフォリオ・ケーススタディ制作
- 公開情報と非公開情報を分離した見せ方

「仕様どおりに画面を作る」だけでなく、何を、どの順番で、どこまで見せれば信頼につながるかを含めて設計します。

## 公開範囲について

このリポジトリは、ポートフォリオサイトの公開用ファイルだけで構成しています。

掲載対象プロジェクトのソースコード、内部アーキテクチャ、運用手順、非公開ログ、認証情報、顧客情報は含めていません。画面内の証拠画像も、公開に必要な結果だけが伝わる形に整理しています。

これは情報を隠して実績を大きく見せるためではなく、技術的な信頼性と守秘の境界を両立させるための判断です。
